# くらしログ

家の「在庫」「やること」（家事・用事・買い物）とレシート・クーポンを iPhone で管理する Web アプリです。

家計の記録・集計は Moneytree で行う（くらしログに家計簿の機能はない）。

- 画面：GitHub Pages で公開する静的サイト（HTML・CSS・JS。ビルド不要）。iPhone のホーム画面に追加して使う
- データ：Google スプレッドシート
- サーバー処理：スプレッドシートに紐づく Google Apps Script（GAS）の Web アプリ。`clasp` で管理する
- 通知：GAS から Discord の Webhook へ送る

## 機能

| タブ | できること |
| --- | --- |
| 在庫 | 商品の登録（賞味期限ごとにロットを分けて管理）、＋−で個数の増減（続けて押したときは、最後に押してから0.6秒待ってまとめて1回で保存する）、商品の編集・削除、カテゴリのタブ（すべて・食品・日用品・医薬品・家具・家電・住宅設備・PC周辺機器・未分類。カテゴリのタブは商品のあるものだけ出し、最後に選んだタブを端末に覚える）、絞り込み（パネルでカテゴリを複数選ぶと「いずれかを含む」。タグは選んでいるカテゴリの中で絞り込む）。型番を入れた商品（家具・家電や設備）は＋−の代わりに型番を表示する。合計が1個で買う目安のない商品に「買い物リストに入れる」を出す（押すと `buyFlag` を `買う` にし、すぐにやることタブの買い物リストに行を作る。もう一度押すと外す。個数が増えると自動で外れる）。商品の編集画面の「買う目安」を入れた商品は、合計がその個数以下で自動で買う物とみなす。買う物のカードには「買う物」バッジを出す（買う物は、やることタブの買い物リストに自動で入る） |
| クーポン | レシートに付いていたクーポン・割引券。タブに期限の近い順の一覧（まだ使えない物は「10/20から」、期限が3日以内は目立たせる）を出し、「使った」「不要」を選ぶ。その下に「レシートから見つかった候補」（レシートの写真に写っていたクーポン・ポイント○倍・キャンペーン・お店の告知）を出し、内容（`title`）と期間をその場で直して「リマインドする」（通常のクーポンにして翌朝から通知）か「不要」 |
| やること | 家事・用事・買い物を、リストごとのリマインダーとして扱う（下の「やることタブ」） |
| 共通 | 在庫のタグ管理（名称変更・統合・一括削除・一括付与）、登録パネルを開いたまま一覧をタップするとフォームに入力、登録・編集画面のタグの候補は選んだカテゴリで使っているタグだけ（ほかのカテゴリのタグも入力欄に入れれば付けられる。カテゴリが未選択なら全タグ。カテゴリを変えても選んだタグは残る） |
| レシート | ヘッダーのカメラのボタンからレシート・クーポン（割引券）を撮影（アルバムからも選べる。長いレシートは「続きを撮る」で同じ1件に写真を足す）。写真は縮めて Google ドライブに保存し、毎晩 0:00 に Claude のスケジュールタスクが読み取って、在庫・クーポン・セール品目に反映する。撮影画面では最近14日に撮った分と未読の件数を見られ、未読の写真は取り消せる。1件をタップすると、在庫（全品目と、自動追加・確認・対象外の判断と理由）・クーポンにどう反映したかを見られ、「在庫の判断を読み直す」で今夜もう一度在庫の判断だけをやり直させられる（ストックタグを後から付けたときなど） |
| 　在庫 | 「レシートから」：Claude が勧める新しい品目（確認待ち）を直して「在庫に追加」か「追加しない」。在庫に登録済み（タグ「ストック」）の品目は Claude が自動で足しており、7日以内なら「取り消す」で個数を戻せる |

### やることタブ

- 最初の画面の上に、カテゴリ（「家事」「買い物」など。「リマインダーカテゴリ」シート）のタブを並べる。タブには、そのカテゴリのリストのまだ終わっていない件数を出す。最後に選んだタブは端末に覚える
  - カテゴリは「やること型」（`type`=`家事`）か「買い物型」（`type`=`買い物`）。中のリストの動き（下の家事のリスト・買い物のリスト）はカテゴリの種類で決まる
  - タブの右端の「管理」：カテゴリの管理（在庫のタグ管理と同じ流れ）。新しいカテゴリを作る（名前と種類）、↑↓でタブを並べ替え、タップで詳細（名前の変更・「リストを入れる」で種類が同じほかのカテゴリのリストを選んで移す・長押しで削除。リストが入っている間は削除できない）
- タブの下に、選んでいるカテゴリのリストのカードを2列に並べる（並び順はリストの `sortOrder`）。カードには、リスト名・まだ終わっていない件数・一言を出す。0件のリストは薄く出す
- 右下の＋：下から出るパネル（在庫の登録パネルと同じ）で新しいリストを作る。名前・カテゴリ（最初は選んでいるタブ。「＋ 新しいカテゴリ」で名前と種類を入れると、リストと一緒にカテゴリも作る）・色、買い物型なら店・在庫に足すか聞く。作ったリストのカテゴリのタブに切り替わる。リストを開いている間は＋を出さない
  - 家事のリストの一言：「期限切れ1件・今日2件」。どちらもなければ次の予定（「次は11/10（火）」）
  - 買い物のリストの一言：その店（リストの `store`）の、使える期間内の未使用のクーポン。くり返し（`repeat`）は今日・明日がその日のときだけ「今日 ふくちゃんデー…」「明日 …」として先に出す。2件以上なら「ほか n件」
- カードをタップすると、リストの画面が右から重なって開く。「‹ リスト」か、画面の左端（24px 以内）から右へのスワイプでカードの画面に戻る。スワイプ中はリストの画面が指について動き、後ろのカードの画面が少し左から寄ってきて、影が薄くなる。画面幅の4割以上動かすか、速く右へはじくと戻り、それ以外は元に戻る。ヘッダーの題名も画面と同じ動きで横にスライドして入れ替わる。iPhone の「視差効果を減らす」がオンなら動かさずに切り替える。開いているタブをもう一度押してもカードの画面に戻る
- リストの画面では、上の入力欄に名前を入れて「追加」で、すぐに追加する。「＋ 個数・メモ・期限を付けて追加」や品目のタップで編集シートを開き、名前・個数・担当（なし / 本人 / 彼女）・メモ・リスト（ほかのリストへ移す）・期限（期限なし / 1回だけ（日付と、任意で時刻）/ くり返す（周期の入力欄））を変えたり、長押しで削除したりする
- 一覧は「今日まで」（期限切れを含む）・「期限なし」・「今後の予定」（期限が明日以降のものと、次の回が先のくり返し）に分ける。期限なしだけのときは見出しを出さない
- 完了は丸のタップ。押した直後の5秒は下に「取り消す」を出す（くり返しは、完了する前の `lastDone`・`nextDue` に戻す）
- 完了したものは「完了 n件」にたたむ。買い物のリストは完了した翌日まで、家事のリストは完了から3日出す（それより前の行はシートに残るが出さない）。くり返しなしの完了は、丸をもう一度押すと「まだ」に戻せる。くり返しと、在庫が足りて自動で完了したものは戻せない
- 買い物の品目には、在庫とつながる品目の在庫の数（「在庫0」「在庫2/目安5」）、「セールチェック」の最新の回（`runId`）の判定（`待ち`＝「セール待ち」、`買い`＝「ネットで買い」）、「セール品目」の1回に買う上限（`maxPack` ÷ `unitQty` に `packUnit` を付けて「2袋まで」。`packUnit` が空なら出さない）を印で出す
- `askStock` が TRUE のリスト（Amazon）では、くり返しでない品目の丸を押すと「在庫に足す？」と個数を聞く。「足して完了」は在庫の登録と同じ処理（賞味期限なしのロットに足す）。取り消すと足した分も減らす。ほかのリストでは、チェックしても在庫の個数は変えない（レシートの自動追加と二重にしない）
- 「リストの管理」（タブの下の右）：選んでいるカテゴリのリストを、↑↓で並べ替え、タップで編集（名前・カテゴリ（種類が同じカテゴリだけ）・店・色・在庫に足すか聞く・表示）。表示を外すとカードを出さない（品目はシートに残る）
- 品目の編集シートの「リスト」は、カテゴリごとにまとめて出す
- タブを開くたびに読み込み直す（5分ごとの処理や在庫の変更で行が増えるため）。読み込み直しに失敗したときは、表示中の内容を残してトーストで知らせる

在庫とのつながり（`gas/reminder.js` の `syncStockReminders`。5分ごとの `checkReminders` と、アプリで在庫を変えたとき・在庫取込を処理したときに行う）：

- 「買う物」（下の「買う物の判定」）になった商品は、買い物リストに行を作る（`source`=`在庫`、`title` と `stockItemName` に在庫の `itemName`）。同じ `stockItemName` のまだ終わっていない行があれば作らない
- 入れるリスト：「セール品目」の `itemName` が同じ行の `baseShop`（`/` 区切りなら前から順に）→「レシート明細」で `matchedStock` がその商品のうち、いちばん新しい（`purchasedAt`）レシートの `store` → そのどれのリストもなければ「その他・店未定」（なければ `store` が空の買い物リスト）。表示中のリストだけが対象
- 店名の合わせ方：NFKC で正規化し、英字を小文字にし、空白と「・」を除いて比べる。リストの `store` には `,` 区切りで別名を書ける（`DAISO,ダイソー`）
- 買う物でなくなったら、`source`=`在庫` のまだ終わっていない行を完了にする（`doneBy`=`自動`）
- 在庫から作った行をアプリで削除すると `status`=`dismissed`・`doneBy`=`アプリ` にし、その商品が一度買う物でなくなるまで作り直さない。買う物でなくなったら `doneBy` を `自動` に書き換えて、作り直さない印を外す
- 手で入れた品目でも、名前が在庫の商品名と同じなら `stockItemName` を入れて在庫の数を出す。ただし自動で完了にするのは `source`=`在庫` の行だけ（手で入れた品目は、在庫が足りていても消えない）。同じ `stockItemName` のまだ終わっていない行があるので、在庫から同じ品目の行は作らない

通知（Discord）：

- 賞味期限：期限が今日〜3日後で、個数が1以上のロットを通知する
- やること（送り先は `DISCORD_WEBHOOK_URL_REMINDER`。なければ `DISCORD_WEBHOOK_URL`。設定は `gas/reminder-notify.js` の先頭の定数）
  - 期限のある行（家事・用事。買い物でも期限を付けたもの）：時刻を指定したものは予定時刻に通知する。期限切れと、時刻を指定していない今日のものは、毎朝 8:00 にまとめて通知する。複数のリストにまたがるときは「ベルク：牛乳」のようにリスト名を付ける
  - 買い物：毎週土曜 8:00 ごろ（8:00 を過ぎた最初の5分ごとの処理）に、まだ終わっていない品目のあるリストごとにカード（embed）を1枚作って送る。カードには品目（個数・メモ・担当・在庫の数・セール待ちなどの印）と、その店の「クーポン」（使える期間内）と「今週の特売日」（その日から7日間の `repeat` の日）を添える。品目のあるリストがなければ送らない。送った日をスクリプトプロパティ `REMINDER_SHOP_SENT` に書き、同じ日に二重に送らない（失敗したら書かず、次の5分ごとの処理で送り直す）
- セールチェック：Claude のスケジュールタスクが毎週「セールチェック」シートに追記した結果（Amazon・Yahoo!ショッピングの価格）を、1時間ごとに確認して1回分（`runId`）ずつ、Discord の埋め込み（embed）で通知する。`notifiedAt` が空の行が未送信で、全メッセージを送信できた回だけ全行に送信日時を書く（途中で失敗したら書かず、次の実行で最初から送り直す）。何か入っている行（「チャットで確認済み」など）は送らない。先頭のメンションは `gas/sale-notify.js` の `SALE_MENTION`。1回分は次の順で最大3メッセージ（送信のあいだに1秒あける）
  - 買い・待ち：1候補を1つの embed にし、「買い」が先で、それぞれ `diffPct` の小さい順に並べる。タイトルに品目名と `diffPct`（押すと商品ページが開く）、本文にサイト・価格・容量・個数、欄に実質単価・普段の単価・期限、フッターに店名と `memo` の最初の文を出す。embed が10個か合計6,000字を超えるときはメッセージを分ける。0件なら「今週は買い・待ちなし」とだけ送る
  - 店頭で買う物：その回に行がある品目のうち、「買い」「待ち」がなく（通知済みの行も含めて見る）、在庫量が `unitQty`（普段の1回分）より少ない品目を、在庫と `basePrice` つきで並べる。在庫量は「在庫」シートの同じ `itemName` の `stock` の合計 × `stockPerUnit`（空なら `unitQty`）。「在庫」シートに行がない品目は除く。対象がなければ送らない
  - まとめ：まとめ行の `memo` を1行ずつ箇条書きにし（改行がない古い形式は「。」で区切る）、内容が「なし」の行を除いて、最後に見送りの件数を足す。1行は60字まで
- クーポンと確認待ち：毎朝 7:00 に、未使用（`status` が空）のクーポンを次の日に通知する。1回の通知の中では「新しいクーポン」「今日から・明日から使える」「期限が近い」の順に並べ、どの行にも使える期間（`10/20〜10/26`。`validFrom` が空なら `〜10/26まで`）を書く。例：`【クーポン】明日から使える：ベルク 次回100円引き（1,000円以上）10/20〜10/26 ※紙のクーポンを持っていく`
  - 新しいクーポン：登録後の最初の朝（`notifiedOn` が空のもの。まだ使えない物も含む）
  - 使える期間が先のもの：`validFrom` の前日（明日から使える）と当日（今日から使える）
  - 期限：`validUntil` の3日前・前日・当日（あと3日・明日まで・今日まで）
  - 通知したクーポンの `notifiedOn` に今日の日付を書き、同じ日に二重に通知しない。期限を過ぎた未使用のクーポンと候補（`status`=`候補`）は `status` を `expired` にする
  - 候補はクーポンの通知に含めない（アプリで「リマインドする」と `status` が空・`notifiedOn` が空になり、翌朝「新しいクーポン」として通知される）
  - 最後に「確認待ち：在庫 n件・クーポン候補 n件」を1行添える（0件の項目は書かない。候補は期限を過ぎていないものを数える）。通知するクーポンも確認待ちもなければ送らない
  - 先頭のメンションは `gas/receipt.js` の `COUPON_MENTION`、行末の一言は `COUPON_REMINDER`

### 画面の動き

- 動きは `transform` と `opacity` だけで行う（GPU で描くので一覧の描き直しや通信を待たせない）。動く時間とイージングは `js/motion.js` と CSS の `--motion-ms`・`--motion-ease` で共通にする。iPhone の「視差効果を減らす」がオンなら動かさずに切り替える
- タブの切り替え：タブバーと同じ並びで画面が横に並んでいるものとして、右のタブなら右から、左のタブなら左から入る。ヘッダーの題名も同じ向きに動く。タブごとにスクロール位置を覚える。タブバーはどこを押しても選んでいるタブのハイライトが指の位置へ向かい、そのまま左右にドラッグすると指について動き、パネルと題名も一緒に動く（タブの端を押しただけでは画面は動かない）（ハイライトが隣のタブまで動くとパネルが画面1枚分動く）。ハイライトは水滴のように動く：タブの上では少し引っかかり（パネルと題名も同じ）、動く速さに合わせて横に伸び、押している間は少し膨らむ。タブを切り替えたときに軽く振動させる（iPhone は iOS 18 からのスイッチの振動を借りる。このスイッチは指を離したときなどユーザーの操作の中でしか振動しないので、iPhone では指を離して切り替わったときだけ、Android ではドラッグ中に選ぶタブが変わるたびに振動させる）。指を離すと一番近いタブ（はじいたときははじいた向きのタブ）へばねで寄せて切り替える（少し行き過ぎてから戻る）。タップで切り替えたときもハイライトはばねで動く。「視差効果を減らす」がオンなら、伸び縮みとばねは使わない
- シート（編集・タグ管理・撮影・削除の確認）は下から出し、後ろを薄く暗くする。登録・絞り込みのパネルはタブバーの後ろから出す（タブを切り替えたときは動かさずに閉じる）
- シートの中で奥へ進む（タグ一覧 → タグ詳細など）と中身と題名が右から入り、「‹ 戻る」で右へ出る
- 数字（在庫の個数・合計、やることのカードの件数）が変わると、増えたら下から上へ、減ったら上から下へロールする。0 になったときは赤く光らせる

```text
  reminder.js         やることタブ（リストのカード、リストの中、完了・取り消し、編集シート、リストの管理）
  main.js             タブ切り替え、再読み込みボタン、起動時のデータ読み込み

gas/                  GAS のコード（clasp push でこのフォルダの中身が GAS に反映される）
  .clasp.json         GAS プロジェクトの scriptId
  appsscript.json     GAS の設定（タイムゾーン Asia/Tokyo、Web アプリの公開設定）
  main.js             doGet / doPost（リクエストの振り分け）と共通の関数
  stock.js            在庫
  tags.js             タグの一括操作
  reminder.js         やること（リストと品目の操作、在庫とのつながり、セットアップ）
  reminder-notify.js  やることの通知（期限・毎朝のまとめ・土曜の買い物）と、5分ごとの checkReminders
  chore-rule.js       くり返しの周期の計算。GAS と画面（index.html から読み込む）の両方で使う
  shared.js           GAS と画面の両方で使う判定（文字列の正規化・タグの分解、買う物の判定、店名の合わせ方、クーポンのくり返し）
  notify.js           Discord への送信、賞味期限の通知
  sale-notify.js      セールチェックの結果（「セールチェック」シート）の通知
  receipt.js          レシート・クーポンの写真の保存、在庫取込・クーポンの一覧と操作、毎朝のクーポンの通知
```

`js/` のファイルは ES モジュールではなく通常の `<script>` で読み込むため、ファイルをまたいで関数や変数をそのまま使える。GAS も同じく、すべてのファイルが1つのプログラムとして動く。

## スプレッドシートの構成

シート名と1行目の見出し（列名）でデータを読み書きする。列の順番は自由だが、列名は変えないこと。

### 在庫（1行＝1ロット）

同じ商品でも賞味期限が違えば別の行になる。画面では商品名ごとにまとめて表示する。

| 列 | 内容 |
| --- | --- |
| `id` | ロットのID（UUID） |
| `itemName` | 商品名 |
| `stock` | 個数 |
| `category` | カテゴリ（同じ商品の全ロットで共通）。`食品`・`日用品`・`医薬品`・`家具・家電`・`住宅設備`・`PC周辺機器` のほか、新しいカテゴリも入れられる。空なら画面の「未分類」に出る（`未分類` と入れても空として保存する）。分類はタグではなくこの列に入れる |
| `location` | 収納場所（同じ商品の全ロットで共通） |
| `tags` | タグ（`,` 区切り。同じ商品の全ロットで共通）。`ストック`・`冷蔵` などの属性に使う |
| `expirationDate` | 賞味期限（`yyyy-MM-dd`。なしなら空） |
| `modelNumber` | 型番（同じ商品の全ロットで共通）。型番を入れた商品は家具・家電や設備の記録として扱い、画面の一覧では＋−を出さずに型番を表示する |
| `lastUpdated` | 最終更新日時 |
| `reorderAt` | 買う目安（同じ商品の全ロットで共通）。0 以上の整数か空。合計個数がこの数以下になったら買う物とみなす。数字でないものは目安なしとして扱う |
| `buyFlag` | 「買い物リストに入れる」の印（同じ商品の全ロットで共通）。`買う` か空。個数が増えたら空にする（**シートに直接個数を足すときも空にする**） |

買う物の判定（`gas/shared.js` の `stockBuyReason`。画面と GAS で共通。商品名ごとに全ロットの `stock` の合計で判断する）：型番の入った商品は対象外。`reorderAt` があれば `合計 <= reorderAt`（`buyFlag` は見ない）。空なら、`buyFlag` が `買う`、またはタグ「ストック」があって合計が 0。

`reorderAt`・`buyFlag` の列がないシートでは、その列を飛ばして動く（「買い物リストに入れる」と「買う目安」の欄は画面に出ない）。

### 以前の家計簿のシート

以前の家計簿のシート（家計簿・取込待ち・取込ルール・定期支出）は 2026/10 までの記録として残しているが、アプリからは読み書きしない。

### 家事（記録）

以前の家事タブのシート（`id`・`taskName`・`cycle`・`lastDone`・`isDone`・`rule`・`nextDue`・`notifiedFor`）。行は「リマインダー」の家事のリストに移した。記録として残しているが、アプリからは読み書きしない。

### リマインダーカテゴリ（1行＝1カテゴリ）

やることタブのカテゴリのタブ。`setupReminderCategories` で作る。

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `name` | カテゴリ名（タブに出す） |
| `type` | `家事`（やること型：期限・くり返し・担当で管理する）/ `買い物`（買い物型：店ごとのリスト。クーポンや在庫とつながる）。中のリストの `kind` になる |
| `sortOrder` | タブの並び順（小さい順） |
| `createdAt` | 作成日時 |

### リマインダーリスト（1行＝1リスト）

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `name` | リスト名 |
| `kind` | `家事` / `買い物`。入っているカテゴリの `type` と同じ値（リストの保存のときに書く）。在庫とのつながり・通知などはこの列を見る |
| `store` | 店名（買い物のリストだけ）。`,` 区切りで別名を書ける（先頭の名前がクーポンの `store` と合うようにする）。空のリストは、店が決まらない在庫の品目の行き先になる |
| `color` | カードと Discord の embed の色（`#RRGGBB`）。空ならアプリの家事の色 |
| `sortOrder` | 並び順（小さい順） |
| `askStock` | TRUE なら、チェックしたときに在庫に足すか聞く |
| `active` | FALSE なら非表示（空は表示） |
| `createdAt` | 作成日時 |
| `categoryId` | 入っているカテゴリの `id`。空なら、アプリでは `kind` と種類が同じ最初のカテゴリに出す |

### リマインダー（1行＝1件）

| 列 | 内容 |
| --- | --- |
| `id` | UUID（家事から移した行は、家事の `id` のまま） |
| `listId` | リマインダーリストの `id` |
| `title` | 名前 |
| `qty` | 個数（`2`・`2袋` など。空でもよい） |
| `memo` | メモ |
| `assignee` | 担当。`本人` / `彼女` / 空 |
| `rule` | くり返しのルール（JSON。形式は `gas/chore-rule.js` の先頭のコメントを参照）。空ならくり返しなし |
| `cycle` | くり返しの説明文（`rule` から自動で作る。例：`毎月第2日曜 10:00`） |
| `nextDue` | 次の予定日時（くり返し）・期限（くり返しなし）。時刻なしはその日の 0:00（くり返しなしで 0:00 ちょうどなら時刻なしとみなす）。期限なしは空 |
| `lastDone` | くり返しを最後に完了した日時 |
| `notifiedFor` | どの予定日時の分まで通知したか（二重通知の防止） |
| `status` | 空＝まだ、`done`（くり返しなしの完了）、`dismissed`（在庫から作った行をアプリで削除した）。くり返しは完了しても空のまま（`lastDone` を書いて `nextDue` を次へ進める） |
| `doneAt` | 完了した日時（`done`・`dismissed` のとき） |
| `doneBy` | `アプリ` / `自動`（在庫が足りて自動で完了した）。`dismissed` の行では、`アプリ` の間は在庫から作り直さない（買う物でなくなったら `自動` にする） |
| `source` | `手入力` / `在庫`（在庫が買う物になって作った）/ `チャット`（チャットから書いた） |
| `stockItemName` | つながる在庫の `itemName`（正規化したもの。なければ空） |
| `createdAt`・`updatedAt` | 作成日時・更新日時 |

チャットからシートに直接行を足すときは、`id`（UUID）・`listId`・`title`・`status`（空）・`source`（`チャット`）・`createdAt` を入れる。

### セール品目の packUnit

「セール品目」の末尾の `packUnit` は、1回に買う上限（`maxPack` ÷ `unitQty`）の単位（`袋`・`箱`・`パック` など）。やることタブと買い物の通知で「2袋まで」と出す。まとめ売りのパック（トイレットペーパー12ロール入りなど）で買う品目だけに入れる。ふだん1個ずつ買う品目（詰め替え・米・調味料・洗顔料など）は空にする（上限は出さない）。セールなどでまとめ売りを買うときに必要なら、その単位を入れてよい。

### レシート（1行＝1回の撮影）

アプリで撮った写真の記録。長いレシートを複数枚に分けて撮ったときは1行にまとめる。`store` 以降は Claude が書く（アプリは表示だけ）。

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `kind` | `レシート` / `クーポン` |
| `fileIds` | ドライブのファイル ID（複数枚は `,` 区切り。撮った順） |
| `uploadedAt` | 撮影（送信）した日時 |
| `status` | 空＝未読（Claude が読む）、`read`、`error`、`skipped`（アプリで取り消したものも `skipped`）、`再読`（アプリで「在庫の判断を読み直す」を押したもの。Claude が在庫の判断だけをやり直して `read` に戻す。`note` に依頼した日時を足す） |
| `store` | 店名 |
| `purchasedAt` | 購入日時 |
| `total` | 合計 |
| `payment` | 支払い方法 |
| `importId` | 以前の家計簿の取り込みで使った列。2026/11 以降は `importId` は書かない |
| `note` | 読み取りのメモ・エラーの内容 |
| `processedAt` | Claude が読み取った日時 |

写真はスクリプトプロパティ `RECEIPT_FOLDER_ID` のフォルダに保存する（なければマイドライブに「くらしログ/レシート」を作って ID を保存する）。ファイル名は `20261018-193005_レシート_1a2b3c4d_1.jpg`（撮影日時・種類・id の先頭8文字・何枚目か）。

### 在庫取込（1行＝1品目）

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `receiptId` | レシートシートの `id` |
| `itemName`・`qty`・`category`・`location`・`tags` | 品目・個数・カテゴリ・収納場所・タグ（アプリで「在庫に追加」したときは直した値で上書きする）。`category` は在庫シートと同じカテゴリ（分からなければ空）で、`tags` に分類は入れない |
| `kind` | `自動`（在庫シートにタグ「ストック」で登録済みの品目。Claude が在庫に直接足す）／ `確認`（新しく在庫管理したほうがよさそうな品目） |
| `status` | `自動追加`（Claude が在庫に足し済み）、空＝確認待ち、`added`、`dismissed`、`undone`（自動追加をアプリで取り消した） |
| `reason` | Claude が追加を勧める理由 |
| `stockRowId` | 自動追加で足した在庫シートの行（ロット）の `id`。取り消すとこのロットの個数を `qty` だけ減らす（0 未満にはしない） |
| `createdAt`・`updatedAt` | 作成日時・アプリで処理した日時。自動追加は `createdAt` から7日間アプリに出す |

### レシート明細（1行＝レシートの1品目）

Claude がレシートの**全品目**を書き、在庫についての判断と理由を残す。アプリの撮影画面で1件をタップしたときの「在庫」に出る。

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `receiptId` | レシートシートの `id` |
| `itemName`・`qty`・`price` | レシートの品名・個数・税込金額 |
| `matchedStock` | 在庫シートで同じ物と判断した商品名（`itemName`）。なければ空 |
| `decision` | `自動追加` / `確認` / `対象外` |
| `reason` | 判断の理由（例：`在庫に登録済み（ストックタグなし）`、`日々の食材`、`外食`） |
| `stockImportId` | 在庫取込の行の `id`（`自動追加`・`確認` のとき） |
| `createdAt`・`updatedAt` | 作成日時・読み直しで書き換えた日時 |

判断のしかた：

| 在庫での状態 | `decision` |
| --- | --- |
| 登録済み・タグ「ストック」あり | `自動追加`（在庫に足し、在庫取込に `kind=自動` で記録） |
| 登録済み・ストックタグなし | `確認`（在庫取込に `kind=確認`。理由に「ストックタグを付けると次から自動で足します」） |
| 未登録で、買い置きして切らさないよう管理する価値がある物 | `確認` |
| それ以外（日々の食材・外食・一度きりの買い物など） | `対象外` |

読み直し（`status=再読`）では、すでに `自動追加`・`added` になった品目はそのままにし（二重に足さない）、ほかの品目の判断をやり直して同じ明細の行を書き換える。明細のないレシート（明細の記録を始める前に読んだもの）は明細を作る。クーポン・セール品目は書き直さない。

### クーポン（1行＝1枚）

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `receiptId`・`fileId` | レシートシートの `id` と、クーポンが写った写真のファイル ID |
| `store` | 店名 |
| `title` | 例：`次回 100円引き` |
| `detail` | 対象・条件（`1,000円以上` など） |
| `validFrom`・`validUntil` | 使える期間（`yyyy-MM-dd`。`validFrom` は空のこともある。候補は両方とも空のこともある）。GAS が作ったシートでは文字列の書式にしてある |
| `status` | 空＝未使用（通知の対象）、`候補`、`used`、`dismissed`、`expired`（期限切れ。毎朝の通知で付ける） |
| `notifiedOn` | 最後に通知した日（`yyyy-MM-dd`）。空なら「新しいクーポン」としてまだ通知していない |
| `createdAt` | 作成日時 |
| `repeat` | くり返し（後から足した末尾の列。なければ GAS が作る）。`monthly:9,19,29`＝毎月その日（`-1` は末日。その月にない日は飛ばす）、`weekly:0,6`＝毎週その曜日（`0`＝日〜`6`＝土）。空ならくり返しなし |

- クーポンとして撮った写真から作る行は `status` を空にする（すぐ通知の対象になる）
- `候補`：レシートとして撮った写真の中に Claude が見つけたクーポン・ポイント○倍・キャンペーン・お店の告知（「毎月9のつく日は会員10%OFF」など）。くり返しの告知や期限が読めなかったものは期間が空のこともある。アプリで確認するまで通知しない。「リマインドする」で直した `title`・`validFrom`・`validUntil`・`repeat` を保存し、`status` と `notifiedOn` を空にする。「不要」で `dismissed`
- `repeat` があるクーポン（`status` が空のもの）は、くり返しの日の前日の朝に「明日は」、当日の朝に「今日は」と通知する。例：`【クーポン】明日は：くすりの福太郎 ふくちゃんデー 会員10%OFF（毎月9・19・29日）`
  - `validFrom`・`validUntil` があれば、その範囲の中の日だけ通知する。`validUntil` を過ぎたら、ほかのクーポンと同じく `expired` にする
  - 新しく登録された（`notifiedOn` が空の）ものは、最初の朝に「新しいクーポン」としてくり返しの説明つきで通知する
  - 1回の通知の中では「新しいクーポン」「今日・明日のくり返し」「今日から・明日から使える」「期限が近い」の順に並べる。`notifiedOn` による同じ日の二重通知の防止はほかのクーポンと同じ
  - アプリでは期間の代わりに「毎月9・19・29日（次は10/19）」のように出し、「使った」の代わりに「もう通知しない」（`dismissed`）だけを出す
  - 候補の「リマインドする」（`coupon` の `remind`）で `repeat` も保存できる（アプリでは毎月・毎週を選び、日付か曜日を入れる）

### 文字の正規化（保存時に NFKC で正規化する）

アプリから保存する文字列は、Unicode の NFKC 正規化と前後の空白の除去（`normText`：`String(s ?? '').normalize('NFKC').trim()`）をしてから書き込む。英数字・記号は半角、カタカナは全角にそろう（例：`（ＳＨＡＲＰ）` → `(SHARP)`、`ＡＢＣ　１２３` → `ABC 123`、`ﾃｨｯｼｭ` → `ティッシュ`）。チャットからスプレッドシートに書き込むときも同じ形にそろえる。

- 対象：在庫の `itemName`・`category`・`location`・`tags`・`modelNumber`、やることの `title`・`qty`・`memo`・`stockItemName`、リストの `name`・`store`、タグ管理のタグ名
- `tags` は区切り（`,`・`，`・`、`）で分けた各タグを正規化し、`,`（半角・空白なし）でつなぎ直す
- 日付・時刻・数値・`id`・`rule`（JSON）は対象外
- GAS（`gas/main.js` の `normText`）で必ず正規化する。画面（`js/common.js` の `normText`）でも送信前に同じ正規化をして、トーストや一覧に出る値と保存される値をそろえる
- 在庫の「同じ商品名・同じ賞味期限なら個数を足す」判定は、正規化した商品名どうしで比べる（全角かっこの `電子レンジ（ＳＨＡＲＰ）` は既存の `電子レンジ(SHARP)` と同じ商品になる）

## GAS の API

画面は `js/common.js` の `GAS_URL`（Web アプリの URL）にリクエストを送る。

### 取得（GET `?action=...`）

| action | 返すもの |
| --- | --- |
| `getAll` | 起動時に使う。`stock`・`reminders`・`stockImports`・`coupons` をまとめて返す（在庫取込とクーポンは行数が少なく、起動がほとんど遅くならないので含める） |
| `getStock` | 在庫の全行 |
| `getReminders` | やること。`lists`（全リスト）、`items`（まだ終わっていない行・くり返しの行・4日以内に完了した行）、`sale`（`items`：品目名 → `{pack: "2袋まで"}`、`verdicts`：品目名 → `買い` / `待ち`（最新の回）） |
| `getReceipts` | 最近14日に撮った分（`recent`。`count` に写真の枚数、`items`・`auto`・`confirm`・`skip` に明細の件数、`coupons` にクーポン・候補の件数）と、今夜読む件数（`unread`。`status` が空か `再読`） |
| `getReceiptDetail` | 撮影した1件（`id`）の反映の詳細。`receipt`・`items`（レシート明細と、対応する在庫取込の行 `stockImport`）・`otherStockImports`・`coupons` |
| `getStockImports` | 在庫取込の確認待ち（`pending`）と、7日以内の自動追加（`auto`）。どちらも `receiptFiles` 付き |
| `getCoupons` | 未使用（`status` が空）と候補（`status`=`候補`）で、期限を過ぎていないクーポン（期限の近い順。画面で `status` によって分けて表示する）。`getAll` にも `coupons` として入る |

### 書き込み（POST。本文は JSON）

| type | action | 内容 |
| --- | --- | --- |
| `stock` | なし | 登録。同じ商品名・同じ賞味期限のロットがあれば個数を足し、なければロットを追加 |
| `stock` | `bump` | ロットの個数を増減（`id`・`value`）。増やしたときは商品の `buyFlag` を空にする |
| `stock` | `setBuyFlag` | 買い物リストに入れる・外す（`target` に商品名、`value` に `true` / `false`）。商品の全ロットの `buyFlag` と `lastUpdated` を更新する |
| `stock` | `editItem` | 商品の編集（商品情報と、賞味期限ごとの個数をまとめて保存） |
| `stock` | `delete` | 商品の全ロットを削除（`target` に商品名） |
| `tag` | `rename` / `delete` / `assign` | 在庫のタグの名称変更・一括削除・一括付与 |
| `receipt` | `upload` | 写真を1枚受け取り、ドライブに保存する（`kind`：`レシート` / `クーポン`、`image`：JPEG の base64。1枚 5MB まで）。`receiptId` があればその1件（未読のものだけ）に写真を足す。返り値に `id`・`count`（その1件の枚数） |
| `receipt` | `skip` | まだ読まれていない1件を読まないようにする（`id`）。`status` を `skipped` にする |
| `receipt` | `reread` | 読み取り済みのレシート（`id`）の在庫の判断を今夜やり直させる。`status` を `再読` にする |
| `stockImport` | `add` | 確認待ちを在庫に登録する（`id`・`itemName`・`qty`・`category`・`location`・`tags`・`expirationDate`。在庫の登録と同じ処理）。`status` を `added` にする |
| `stockImport` | `dismiss` | 確認待ちを追加しない（`id`）。`status` を `dismissed` にする |
| `stockImport` | `undo` | 自動追加を取り消す（`id`）。`stockRowId` のロットの個数を `qty` だけ減らし、`status` を `undone` にする。ロットが見つからなければ個数は変えず、返り値の `message` で知らせる |
| `coupon` | `used` / `dismiss` | クーポンを使った（`used`）・不要（`dismissed`）にする（`id`）。`used` は未使用のクーポンだけ、`dismiss` は未使用のクーポンと候補 |
| `coupon` | `remind` | 候補をクーポンにする（`id`・`title`・`validFrom`・`validUntil`。期間は `yyyy-MM-dd` か空）。内容を保存し、`status` と `notifiedOn` を空にする |

| `reminder` | `add` / `edit` | やることの追加・編集（`listId`・`title`・`qty`・`memo`・`assignee`、くり返しなら `rule`、くり返しなしなら `due`（`yyyy-MM-dd` か `yyyy-MM-ddTHH:mm`。期限なしは空））。`edit` は `id` で指定。返り値の `item` に書き込んだ後の行 |
| `reminder` | `done` | 完了（`id`）。くり返しは `lastDone` を書いて `nextDue` を次へ、くり返しなしは `status`=`done`・`doneAt`・`doneBy`=`アプリ`。`addStock`（個数）があれば在庫に足す |
| `reminder` | `undo` | 完了を取り消す（`id`）。くり返しは `prev`（`lastDone`・`nextDue`・`notifiedFor`）に戻す。くり返しなしは `status` などを空に戻す。`removeStock`（個数）があれば `done` で足した在庫を減らす |
| `reminder` | `delete` | 削除（`id`）。在庫から作った行は `status`=`dismissed`、それ以外は行を消す |
| `reminderList` | `add` / `edit` | リストの追加（`name`・`categoryId`・`store`・`color`・`askStock`。新しいカテゴリに入れるなら `categoryId` の代わりに `newCategory`：`{name, type}`）・編集（`id`・`name`・`categoryId`・`store`・`color`・`askStock`・`active`）。`kind` はカテゴリの `type` にする。編集で移せるのは `type` が同じカテゴリだけ。返り値の `list` に書き込んだ後の行（`newCategory` で作ったときは `list.category` にそのカテゴリ） |
| `reminderList` | `reorder` | 並べ替え（`ids` にリストの `id` を並べたい順に。`sortOrder` を振り直す） |
| `reminderCategory` | `add` / `rename` | カテゴリの追加（`name`・`type`）・名前の変更（`id`・`name`）。返り値の `category` に書き込んだ後の行 |
| `reminderCategory` | `delete` | カテゴリの削除（`id`）。リストが入っていればエラー |
| `reminderCategory` | `reorder` | タブの並べ替え（`ids` にカテゴリの `id` を並べたい順に） |
| `reminderCategory` | `move` | `listIds` のリストをカテゴリ（`id`）に移す。`type` が違うリストがあればエラー |

`coupon` の操作は、対象の `status` でない（すでに処理済み）ならエラーを返す。在庫を変える操作（`stock`・`stockImport`）のあとは、買い物リストへの反映（`syncStockReminders`）も行う（失敗しても在庫の操作は成功として返し、5分ごとの処理でもう一度合わせる）。

返り値は `{ "status": "success" }` または `{ "status": "error", "message": "..." }`。

シートの「読む → 書く」の途中にほかの書き込みが入らないよう、書き込みはスクリプトのロック（`LockService.getScriptLock`）の中で行う。在庫の操作（`stockAction`）・在庫取込の追加と取り消しでは、在庫を書いたあと同じロックの中で買い物リストにも反映する（`syncStockRemindersSafe`）。5分ごとの処理・通知・天気の通知も同じロックを使うので、それらが動いている間は書き込みが少し待たされる（20秒待っても取れなければエラーを返す）。

## セットアップ

### 1. GAS

1. `gas/` フォルダで `clasp push` する
2. GAS エディタの「プロジェクトの設定」→「スクリプト プロパティ」に `DISCORD_WEBHOOK_URL`（Discord の Webhook URL）を追加する
   - 通知を別のチャンネルに分けたいときは、そのチャンネルの Webhook URL を次のプロパティに追加する（未設定のものは `DISCORD_WEBHOOK_URL` に送られる）
     - `DISCORD_WEBHOOK_URL_EXPIRATION`：賞味期限アラート
     - `DISCORD_WEBHOOK_URL_COUPON`：クーポンの期限と確認待ちの件数
     - `DISCORD_WEBHOOK_URL_SALE`：セールチェック
     - `DISCORD_WEBHOOK_URL_WEATHER`：天気の通知（朝の天気・電車の運行情報の変化・夜の明日の注意）
     - `DISCORD_WEBHOOK_URL_REMINDER`：やることの通知（期限・毎朝のまとめ・土曜の買い物）
3. GAS エディタで次のトリガーを用意する
   - `setupReminders` を一度実行する（「リマインダーリスト」「リマインダー」シートと最初のリストを作り、`checkReminders` を5分ごとに実行するトリガーを作り、今の在庫から買い物リストの行を作る。何度実行しても重複しない）
   - `setupReminderCategories` を一度実行する（「リマインダーカテゴリ」シートと「リマインダーリスト」の `categoryId` 列を作り、「家事」「買い物」のカテゴリを作って、カテゴリのないリストを `kind` と同じ名前のカテゴリに入れる。何度実行しても重複しない）
   - `checkExpirationAndNotifyDiscord` を1日1回実行する時間主導型トリガーを作る
   - `setupSaleCheckTrigger` を一度実行する（`notifySaleCheck` を1時間ごとに実行するトリガーが作られる。何度実行しても重複しない）
   - `setupWeatherTrigger` を一度実行する（`weatherTick` を5分ごとに実行するトリガーが作られる。何度実行しても重複しない）。朝 5:05 に天気の通知、21:00 に明日の注意（あるときだけ）を送る。電車の運行情報は `WX_TRAIN_ENABLED` を true にしたときだけ入れる（今は false。乗換案内アプリで見る）。時刻・場所・路線は `gas/weather-notify.js` の先頭の設定で変える
   - `setupReceiptTriggers` を一度実行する（`notifyCouponsAndPending` を毎朝 7:00 に実行するトリガーが作られる。何度実行しても重複しない）。あわせて「レシート」「在庫取込」「クーポン」シートを用意し、写真の保存先のフォルダを作る。初回はドライブの権限の許可を求められる
4. Web アプリとしてデプロイし、URL を `js/common.js` の `GAS_URL` に入れる

天気の通知は `debugWeatherPreview`（ログに出すだけ。カードの下の行に、1時間ごとの予報をどこから読めたかが出る）・`debugWeatherMorningNow`（いま送る）で確かめられる。セールチェックの通知（ペイロードの JSON）は `debugSaleCheckPreview`、クーポンの通知文は `debugCouponNotifyPreview`、やることの期限の通知文は `debugReminderNotifyPreview`、土曜の買い物の通知（ペイロードの JSON。曜日・時刻に関係なく今の内容で作る）は `debugShoppingNotifyPreview` でログに出せる（送信もシートへの書き込みもしない）。

レシートの読み取りは、アプリの外で用意した Claude のスケジュールタスクが毎晩 0:00 に行う。「レシート」シートの `status` が空の行の写真（`fileIds`）を読み、上の「スプレッドシートの構成」のとおりに「レシート」「レシート明細」「在庫取込」「クーポン」シートへ書き込む。`status` が `再読` の行は在庫の判断だけをやり直す（在庫の自動追加では在庫シートの個数も足し、足したロットの `id` を `stockRowId` に入れる。このとき同じ商品の全ロットの `buyFlag` を空にする。新しいロットを作るときは `reorderAt` を既存のロットから写す）。

## 更新の手順

### GAS を変更したとき

`clasp push` だけでは公開中の Web アプリは変わらない。デプロイを更新する（URL は変わらない）。

```sh
cd gas
clasp push
clasp deploy -i AKfycbzCsng8oDxwQnSnUlxz1m3ANECSSH1tkmK1GIhowAkyhAM_ao7BydA1venB-zGssbL1 -d "変更内容"
```

`clasp push` は GAS 側を手元の `gas/` と同じ状態にする（手元にないファイルは GAS から消える）。

### 画面を変更したとき

`main` に push すると GitHub Pages に反映される（1分ほどかかる）。

- GitHub Pages は10分間キャッシュされる。アプリのヘッダー右上の再読み込みボタンを押すと、キャッシュを使わずに最新版を読み込む
- ホーム画面のアイコンや `<head>` の `apple-mobile-web-app-*` の設定を変えたときは、ホーム画面のアイコンを削除して追加し直す必要がある

## 開発時の注意

- **見た目（テーマ「スレート」）**：暗めのグレー背景・くすんだアクセント色・丸ゴシックのダークテーマ
  - 色は `css/style.css` の `:root` の変数で決める。在庫・クーポン・やることのアクセント色（`--stock`・`--coupon`・`--chore`）と、その暗い版（`-dim`。選択中のタブなどの背景）がある。アクセント色の上に載る文字は `--on-accent`
  - 文字と背景のコントラストは本文で 4.5:1 以上にしている（`--muted` の文字は `--surface-2` の上でも 4.5:1 以上）。色を変えたときは確かめ直す
  - フォントは Google Fonts の「M PLUS Rounded 1c」。読み込めないときは端末のフォント（ヒラギノ角ゴなど）になる
- **ステータスバーの設定**：`apple-mobile-web-app-status-bar-style` は `black` にしている。`black-translucent` にすると、iOS 26 のホーム画面アプリで表示領域が画面の下端まで届かず、画面の下に空白ができる
  - ホーム画面アプリでは、iOS がステータスバーの下に少しはみ出すぼかしを重ねる（Safari では出ず、スクロールしても変わらない）。ヘッダーの上の余白を 12px にしていたときはロゴの行がぼかしにかかったため、`calc(22px + var(--safe-top))` にしている。iOS 27.2 で確かめた
- **タブバー**：画面の下に浮いた丸型のバー。背景がカードの面と近いので、縁に1pxの線（`--border`）を付けて区別している。下端から `max(12px, env(safe-area-inset-bottom) - 4px)` 離して置くので、ホームバーとは重ならない。バーの周りと下には一覧（背景は `--bg`）がそのまま見える。登録パネル・登録ボタン（FAB）・トースト・一覧の下の余白は、`--tabbar-h`（バーの高さ 66px と下の余白の合計）を基準に置いている。選んでいるタブのハイライトはボタンごとの背景ではなく、ボタンの後ろに1つだけ置いた `.tab-thumb` で、位置と形（伸び縮み）は js/main.js が毎フレーム計算して transform で動かす（色はバーの `data-active` で決める）。バーの端からはみ出しても浮いて見えないよう、ハイライトはタブの色を16%だけ透かしたガラスにし、縁の線と上端の光で形を見せて後ろをぼかす（16% はタブの色の文字が 4.5:1 以上になる濃さ）。引っかかりの強さ・ばね・伸びる量は `THUMB_` で始まる定数で変えられる
- **通信**：GAS の応答はふだん1〜3秒だが、混み具合によって数十秒かかることがある。そのため `js/common.js` で次のようにしている
  - 取得（`getFromGas`）：20秒で打ち切り、最大2回まで再試行する
  - 書き込み（`postToGas`）：60秒まで待つ。時間切れでも GAS 側では処理が済んでいることがあり、再試行すると二重に書き込むおそれがあるので、自動では再試行しない
  - 失敗したときは、一覧に理由（時間切れ・通信エラー・GAS のエラーの内容）と「もう一度読み込む」ボタンを出す
- **日付**：GAS は `Asia/Tokyo` で動く。やることの予定日時は、日本時間で計算する
- **写真**：送る前に画面で長い辺 1600px・JPEG（品質 0.8）に縮める（iPhone の HEIC もここで JPEG になる）。1枚ずつ送るので、時間切れになっても撮った写真がまとめて失われることはない。時間切れのときは、撮影画面の「今日撮った分」で届いたか確かめる
- **動作確認**：手元では Edge のヘッドレスモードで `index.html` を開いてスクリーンショットを撮れる（`msedge --headless=new --screenshot=... --window-size=520,900 file:///.../index.html`）。ヘッドレスの Edge は幅が約500px より狭くならない
