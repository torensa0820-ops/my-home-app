# くらしログ

家の「在庫」「家事」とレシート・クーポンを iPhone で管理する Web アプリです。

家計の記録・集計は Moneytree で行う（くらしログに家計簿の機能はない）。

- 画面：GitHub Pages で公開する静的サイト（HTML・CSS・JS。ビルド不要）。iPhone のホーム画面に追加して使う
- データ：Google スプレッドシート
- サーバー処理：スプレッドシートに紐づく Google Apps Script（GAS）の Web アプリ。`clasp` で管理する
- 通知：GAS から Discord の Webhook へ送る

## 機能

| タブ | できること |
| --- | --- |
| 在庫 | 商品の登録（賞味期限ごとにロットを分けて管理）、＋−で個数の増減、商品の編集・削除、カテゴリのタブ（すべて・買う物・食品・日用品・医薬品・家具・家電・住宅設備・PC周辺機器・未分類。カテゴリのタブは商品のあるものだけ出し、最後に選んだタブを端末に覚える）、絞り込み（パネルでカテゴリを複数選ぶと「いずれかを含む」。タグは選んでいるカテゴリの中で絞り込む）。型番を入れた商品（家具・家電や設備）は＋−の代わりに型番を表示する。買い物メモ：合計が1個で買う目安のない商品に「買い物メモに追加」を出す（押すと「メモに追加済み」、もう一度押すと外す。個数が増えると自動で外れる）。商品の編集画面の「買う目安」を入れた商品は、合計がその個数以下で自動で買う物とみなす。「買う物」タブに買う物（理由つき：残り n 個（目安 m）・メモに追加・切らしている）をチェックボックス付きで出し、「選んだ物をコピー」で商品名を1行に1品目コピーする（iPhone のショートカットで共有のリマインダーに入れる）。ほかのタブのカードにも「買う物」バッジを出す |
| クーポン | レシートに付いていたクーポン・割引券。タブに期限の近い順の一覧（まだ使えない物は「10/20から」、期限が3日以内は目立たせる）を出し、「使った」「不要」を選ぶ。その下に「レシートから見つかった候補」（レシートの写真に写っていたクーポン・ポイント○倍・キャンペーン・お店の告知）を出し、内容（`title`）と期間をその場で直して「リマインドする」（通常のクーポンにして翌朝から通知）か「不要」 |
| 家事 | 周期（N日ごと・N週ごと・毎月何日・毎月第何週何曜日・完了からN日後）と時刻の設定、長押しで完了すると次の予定日時へ進む、家事の編集・削除 |
| 共通 | 在庫のタグ管理（名称変更・統合・一括削除・一括付与）、登録パネルを開いたまま一覧をタップするとフォームに入力、登録・編集画面のタグの候補は選んだカテゴリで使っているタグだけ（ほかのカテゴリのタグも入力欄に入れれば付けられる。カテゴリが未選択なら全タグ。カテゴリを変えても選んだタグは残る） |
| レシート | ヘッダーのカメラのボタンからレシート・クーポン（割引券）を撮影（アルバムからも選べる。長いレシートは「続きを撮る」で同じ1件に写真を足す）。写真は縮めて Google ドライブに保存し、毎晩 0:00 に Claude のスケジュールタスクが読み取って、在庫・クーポン・セール品目に反映する。撮影画面では最近14日に撮った分と未読の件数を見られ、未読の写真は取り消せる。1件をタップすると、在庫（全品目と、自動追加・確認・対象外の判断と理由）・クーポンにどう反映したかを見られ、「在庫の判断を読み直す」で今夜もう一度在庫の判断だけをやり直させられる（ストックタグを後から付けたときなど） |
| 　在庫 | 「レシートから」：Claude が勧める新しい品目（確認待ち）を直して「在庫に追加」か「追加しない」。在庫に登録済み（タグ「ストック」）の品目は Claude が自動で足しており、7日以内なら「取り消す」で個数を戻せる |

通知（Discord）：

- 賞味期限：期限が今日〜3日後で、個数が1以上のロットを通知する
- 家事：時刻を指定した家事は予定時刻に通知する。期限切れの家事と、時刻を指定していない今日の家事は、毎朝 8:00 にまとめて通知する
- セールチェック：Claude のスケジュールタスクが毎週「セールチェック」シートに追記した結果（Amazon・Yahoo!ショッピングの価格）を、1時間ごとに確認して1回分（`runId`）ずつ通知する。`notifiedAt` が空の行が未送信で、送信できた回の全行に送信日時を書く。何か入っている行（「チャットで確認済み」など）は送らない。先頭のメンションは `gas/sale-notify.js` の `SALE_MENTION`
- クーポンと確認待ち：毎朝 7:00 に、未使用（`status` が空）のクーポンを次の日に通知する。1回の通知の中では「新しいクーポン」「今日から・明日から使える」「期限が近い」の順に並べ、どの行にも使える期間（`10/20〜10/26`。`validFrom` が空なら `〜10/26まで`）を書く。例：`【クーポン】明日から使える：ベルク 次回100円引き（1,000円以上）10/20〜10/26 ※紙のクーポンを持っていく`
  - 新しいクーポン：登録後の最初の朝（`notifiedOn` が空のもの。まだ使えない物も含む）
  - 使える期間が先のもの：`validFrom` の前日（明日から使える）と当日（今日から使える）
  - 期限：`validUntil` の3日前・前日・当日（あと3日・明日まで・今日まで）
  - 通知したクーポンの `notifiedOn` に今日の日付を書き、同じ日に二重に通知しない。期限を過ぎた未使用のクーポンと候補（`status`=`候補`）は `status` を `expired` にする
  - 候補はクーポンの通知に含めない（アプリで「リマインドする」と `status` が空・`notifiedOn` が空になり、翌朝「新しいクーポン」として通知される）
  - 最後に「確認待ち：在庫 n件・クーポン候補 n件」を1行添える（0件の項目は書かない。候補は期限を過ぎていないものを数える）。通知するクーポンも確認待ちもなければ送らない
  - 先頭のメンションは `gas/receipt.js` の `COUPON_MENTION`、行末の一言は `COUPON_REMINDER`

js/                   画面の処理。index.html で上から順に読み込む（順番に意味がある）
  common.js           GAS_URL、GASとの通信、トースト、要素作成 h()、日付・タグの小さな関数
  panels.js           下から出るパネル（登録フォーム・絞り込み）、編集用のシート、長押しボタン
  tags.js             タグの選択、一覧の絞り込み、タグ管理
  stock.js            在庫
  stock-import.js     在庫の「レシートから」（確認待ちの追加・追加しない、自動追加の取り消し）
  coupon.js           クーポンの一覧（使った・不要）と、レシートから見つかった候補（直してリマインドする・不要）
  receipt.js          レシート・クーポンの撮影（写真を縮めて送る）、最近撮った分と1件の反映の詳細、在庫の判断の読み直し
  chore.js            家事
  main.js             タブ切り替え、再読み込みボタン、起動時のデータ読み込み

  .clasp.json         GAS プロジェクトの scriptId
  appsscript.json     GAS の設定（タイムゾーン Asia/Tokyo、Web アプリの公開設定）
  main.js             doGet / doPost（リクエストの振り分け）と共通の関数
  stock.js            在庫
  tags.js             タグの一括操作
  chore.js            家事（登録・完了・編集・削除・通知）

  sale-notify.js      セールチェックの結果（「セールチェック」シート）の通知

`js/` のファイルは ES モジュールではなく通常の `<script>` で読み込むため、ファイルをまたいで関数や変数をそのまま使える。GAS も同じく、すべてのファイルが1つのプログラムとして動く。

## スプレッドシートの構成

シート名と1行目の見出し（列名）でデータを読み書きする。列の順番は自由だが、列名は変えないこと。

### 在庫（1行＝1ロット）

同じ商品でも賞味期限が違えば別の行になる。画面では商品名ごとにまとめて表示する。

| 列 | 内容 |
| --- | --- |
| `id` | ロットのID（UUID） |
| `itemName` | 商品名 |
| `stock` | 個数 |
| `category` | カテゴリ（同じ商品の全ロットで共通）。`食品`・`日用品`・`医薬品`・`家具・家電`・`住宅設備`・`PC周辺機器` のほか、新しいカテゴリも入れられる。空なら画面の「未分類」に出る（`未分類` と入れても空として保存する）。分類はタグではなくこの列に入れる |
| `location` | 収納場所（同じ商品の全ロットで共通） |
| `tags` | タグ（`,` 区切り。同じ商品の全ロットで共通）。`ストック`・`冷蔵` などの属性に使う |
| `expirationDate` | 賞味期限（`yyyy-MM-dd`。なしなら空） |
| `modelNumber` | 型番（同じ商品の全ロットで共通）。型番を入れた商品は家具・家電や設備の記録として扱い、画面の一覧では＋−を出さずに型番を表示する |
| `lastUpdated` | 最終更新日時 |
| `reorderAt` | 買う目安（同じ商品の全ロットで共通）。0 以上の整数か空。合計個数がこの数以下になったら買う物とみなす。数字でないものは目安なしとして扱う |
| `buyFlag` | 買い物メモの印（同じ商品の全ロットで共通）。`買う` か空。個数が増えたら空にする（**シートに直接個数を足すときも空にする**） |

買う物の判定（画面の `isBuyItem`）：型番の入った商品は対象外。`reorderAt` があれば `合計 <= reorderAt`（`buyFlag` は見ない）。空なら、`buyFlag` が `買う`、またはタグ「ストック」があって合計が 0。

`reorderAt`・`buyFlag` の列がないシートでは、その列を飛ばして動く（「買い物メモに追加」と「買う目安」の欄は画面に出ない）。

### 以前の家計簿のシート

以前の家計簿のシート（家計簿・取込待ち・取込ルール・定期支出）は 2026/10 までの記録として残しているが、アプリからは読み書きしない。

### 家事

| 列 | 内容 |
| --- | --- |
| `id` | 家事のID（UUID） |
| `taskName` | 家事名 |
| `rule` | 周期のルール（JSON。形式は `gas/chore-rule.js` の先頭のコメントを参照） |
| `cycle` | 周期の説明文（`rule` から自動で作る。例：`毎月第2日曜 10:00`） |
| `nextDue` | 次の予定日時（時刻なしの家事はその日の 0:00） |
| `lastDone` | 最後に完了した日時 |
| `notifiedFor` | どの予定日時の分まで通知したか（二重通知の防止） |

`rule`・`nextDue`・`notifiedFor` などの列がなければ、最初に登録したときに自動で追加される。

### レシート（1行＝1回の撮影）

アプリで撮った写真の記録。長いレシートを複数枚に分けて撮ったときは1行にまとめる。`store` 以降は Claude が書く（アプリは表示だけ）。

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `kind` | `レシート` / `クーポン` |
| `fileIds` | ドライブのファイル ID（複数枚は `,` 区切り。撮った順） |
| `uploadedAt` | 撮影（送信）した日時 |
| `status` | 空＝未読（Claude が読む）、`read`、`error`、`skipped`（アプリで取り消したものも `skipped`）、`再読`（アプリで「在庫の判断を読み直す」を押したもの。Claude が在庫の判断だけをやり直して `read` に戻す。`note` に依頼した日時を足す） |
| `store` | 店名 |
| `purchasedAt` | 購入日時 |
| `total` | 合計 |
| `payment` | 支払い方法 |
| `importId` | 以前の家計簿の取り込みで使った列。2026/11 以降は `importId` は書かない |
| `note` | 読み取りのメモ・エラーの内容 |
| `processedAt` | Claude が読み取った日時 |

写真はスクリプトプロパティ `RECEIPT_FOLDER_ID` のフォルダに保存する（なければマイドライブに「くらしログ/レシート」を作って ID を保存する）。ファイル名は `20261018-193005_レシート_1a2b3c4d_1.jpg`（撮影日時・種類・id の先頭8文字・何枚目か）。

### 在庫取込（1行＝1品目）

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `receiptId` | レシートシートの `id` |
| `itemName`・`qty`・`category`・`location`・`tags` | 品目・個数・カテゴリ・収納場所・タグ（アプリで「在庫に追加」したときは直した値で上書きする）。`category` は在庫シートと同じカテゴリ（分からなければ空）で、`tags` に分類は入れない |
| `kind` | `自動`（在庫シートにタグ「ストック」で登録済みの品目。Claude が在庫に直接足す）／ `確認`（新しく在庫管理したほうがよさそうな品目） |
| `status` | `自動追加`（Claude が在庫に足し済み）、空＝確認待ち、`added`、`dismissed`、`undone`（自動追加をアプリで取り消した） |
| `reason` | Claude が追加を勧める理由 |
| `stockRowId` | 自動追加で足した在庫シートの行（ロット）の `id`。取り消すとこのロットの個数を `qty` だけ減らす（0 未満にはしない） |
| `createdAt`・`updatedAt` | 作成日時・アプリで処理した日時。自動追加は `createdAt` から7日間アプリに出す |

### レシート明細（1行＝レシートの1品目）

Claude がレシートの**全品目**を書き、在庫についての判断と理由を残す。アプリの撮影画面で1件をタップしたときの「在庫」に出る。

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `receiptId` | レシートシートの `id` |
| `itemName`・`qty`・`price` | レシートの品名・個数・税込金額 |
| `matchedStock` | 在庫シートで同じ物と判断した商品名（`itemName`）。なければ空 |
| `decision` | `自動追加` / `確認` / `対象外` |
| `reason` | 判断の理由（例：`在庫に登録済み（ストックタグなし）`、`日々の食材`、`外食`） |
| `stockImportId` | 在庫取込の行の `id`（`自動追加`・`確認` のとき） |
| `createdAt`・`updatedAt` | 作成日時・読み直しで書き換えた日時 |

判断のしかた：

| 在庫での状態 | `decision` |
| --- | --- |
| 登録済み・タグ「ストック」あり | `自動追加`（在庫に足し、在庫取込に `kind=自動` で記録） |
| 登録済み・ストックタグなし | `確認`（在庫取込に `kind=確認`。理由に「ストックタグを付けると次から自動で足します」） |
| 未登録で、買い置きして切らさないよう管理する価値がある物 | `確認` |
| それ以外（日々の食材・外食・一度きりの買い物など） | `対象外` |

読み直し（`status=再読`）では、すでに `自動追加`・`added` になった品目はそのままにし（二重に足さない）、ほかの品目の判断をやり直して同じ明細の行を書き換える。明細のないレシート（明細の記録を始める前に読んだもの）は明細を作る。クーポン・セール品目は書き直さない。

### クーポン（1行＝1枚）

| 列 | 内容 |
| --- | --- |
| `id` | UUID |
| `receiptId`・`fileId` | レシートシートの `id` と、クーポンが写った写真のファイル ID |
| `store` | 店名 |
| `title` | 例：`次回 100円引き` |
| `detail` | 対象・条件（`1,000円以上` など） |
| `validFrom`・`validUntil` | 使える期間（`yyyy-MM-dd`。`validFrom` は空のこともある。候補は両方とも空のこともある）。GAS が作ったシートでは文字列の書式にしてある |
| `status` | 空＝未使用（通知の対象）、`候補`、`used`、`dismissed`、`expired`（期限切れ。毎朝の通知で付ける） |
| `notifiedOn` | 最後に通知した日（`yyyy-MM-dd`）。空なら「新しいクーポン」としてまだ通知していない |
| `createdAt` | 作成日時 |
| `repeat` | くり返し（後から足した末尾の列。なければ GAS が作る）。`monthly:9,19,29`＝毎月その日（`-1` は末日。その月にない日は飛ばす）、`weekly:0,6`＝毎週その曜日（`0`＝日〜`6`＝土）。空ならくり返しなし |

- クーポンとして撮った写真から作る行は `status` を空にする（すぐ通知の対象になる）
- `候補`：レシートとして撮った写真の中に Claude が見つけたクーポン・ポイント○倍・キャンペーン・お店の告知（「毎月9のつく日は会員10%OFF」など）。くり返しの告知や期限が読めなかったものは期間が空のこともある。アプリで確認するまで通知しない。「リマインドする」で直した `title`・`validFrom`・`validUntil`・`repeat` を保存し、`status` と `notifiedOn` を空にする。「不要」で `dismissed`
- `repeat` があるクーポン（`status` が空のもの）は、くり返しの日の前日の朝に「明日は」、当日の朝に「今日は」と通知する。例：`【クーポン】明日は：くすりの福太郎 ふくちゃんデー 会員10%OFF（毎月9・19・29日）`
  - `validFrom`・`validUntil` があれば、その範囲の中の日だけ通知する。`validUntil` を過ぎたら、ほかのクーポンと同じく `expired` にする
  - 新しく登録された（`notifiedOn` が空の）ものは、最初の朝に「新しいクーポン」としてくり返しの説明つきで通知する
  - 1回の通知の中では「新しいクーポン」「今日・明日のくり返し」「今日から・明日から使える」「期限が近い」の順に並べる。`notifiedOn` による同じ日の二重通知の防止はほかのクーポンと同じ
  - アプリでは期間の代わりに「毎月9・19・29日（次は10/19）」のように出し、「使った」の代わりに「もう通知しない」（`dismissed`）だけを出す
  - 候補の「リマインドする」（`coupon` の `remind`）で `repeat` も保存できる（アプリでは毎月・毎週を選び、日付か曜日を入れる）

### 文字の正規化（保存時に NFKC で正規化する）

アプリから保存する文字列は、Unicode の NFKC 正規化と前後の空白の除去（`normText`：`String(s ?? '').normalize('NFKC').trim()`）をしてから書き込む。英数字・記号は半角、カタカナは全角にそろう（例：`（ＳＨＡＲＰ）` → `(SHARP)`、`ＡＢＣ　１２３` → `ABC 123`、`ﾃｨｯｼｭ` → `ティッシュ`）。チャットからスプレッドシートに書き込むときも同じ形にそろえる。

- 対象：在庫の `itemName`・`category`・`location`・`tags`・`modelNumber`、家事の `taskName`、タグ管理のタグ名
- `tags` は区切り（`,`・`，`・`、`）で分けた各タグを正規化し、`,`（半角・空白なし）でつなぎ直す
- 日付・時刻・数値・`id`・`rule`（JSON）は対象外
- GAS（`gas/main.js` の `normText`）で必ず正規化する。画面（`js/common.js` の `normText`）でも送信前に同じ正規化をして、トーストや一覧に出る値と保存される値をそろえる
- 在庫の「同じ商品名・同じ賞味期限なら個数を足す」判定は、正規化した商品名どうしで比べる（全角かっこの `電子レンジ（ＳＨＡＲＰ）` は既存の `電子レンジ(SHARP)` と同じ商品になる）

## GAS の API

画面は `js/common.js` の `GAS_URL`（Web アプリの URL）にリクエストを送る。

### 取得（GET `?action=...`）

| action | 返すもの |
| --- | --- |
| `getAll` | 起動時に使う。`stock`・`tasks`・`stockImports`・`coupons` をまとめて返す（在庫取込とクーポンは行数が少なく、起動がほとんど遅くならないので含める） |
| `getStock` | 在庫の全行 |
| `getTasks` | 家事の全行 |
| `getReceipts` | 最近14日に撮った分（`recent`。`count` に写真の枚数、`items`・`auto`・`confirm`・`skip` に明細の件数、`coupons` にクーポン・候補の件数）と、今夜読む件数（`unread`。`status` が空か `再読`） |
| `getReceiptDetail` | 撮影した1件（`id`）の反映の詳細。`receipt`・`items`（レシート明細と、対応する在庫取込の行 `stockImport`）・`otherStockImports`・`coupons` |
| `getStockImports` | 在庫取込の確認待ち（`pending`）と、7日以内の自動追加（`auto`）。どちらも `receiptFiles` 付き |
| `getCoupons` | 未使用（`status` が空）と候補（`status`=`候補`）で、期限を過ぎていないクーポン（期限の近い順。画面で `status` によって分けて表示する）。`getAll` にも `coupons` として入る |

### 書き込み（POST。本文は JSON）

| type | action | 内容 |
| --- | --- | --- |
| `stock` | なし | 登録。同じ商品名・同じ賞味期限のロットがあれば個数を足し、なければロットを追加 |
| `stock` | `bump` | ロットの個数を増減（`id`・`value`）。増やしたときは商品の `buyFlag` を空にする |
| `stock` | `setBuyFlag` | 買い物メモの印を付ける・外す（`target` に商品名、`value` に `true` / `false`）。商品の全ロットの `buyFlag` と `lastUpdated` を更新する |
| `stock` | `editItem` | 商品の編集（商品情報と、賞味期限ごとの個数をまとめて保存） |
| `stock` | `delete` | 商品の全ロットを削除（`target` に商品名） |
| `tag` | `rename` / `delete` / `assign` | タグの名称変更・一括削除・一括付与（`sheet` は `stock`） |
| `receipt` | `upload` | 写真を1枚受け取り、ドライブに保存する（`kind`：`レシート` / `クーポン`、`image`：JPEG の base64。1枚 5MB まで）。`receiptId` があればその1件（未読のものだけ）に写真を足す。返り値に `id`・`count`（その1件の枚数） |
| `receipt` | `skip` | まだ読まれていない1件を読まないようにする（`id`）。`status` を `skipped` にする |
| `receipt` | `reread` | 読み取り済みのレシート（`id`）の在庫の判断を今夜やり直させる。`status` を `再読` にする |
| `stockImport` | `add` | 確認待ちを在庫に登録する（`id`・`itemName`・`qty`・`category`・`location`・`tags`・`expirationDate`。在庫の登録と同じ処理）。`status` を `added` にする |
| `stockImport` | `dismiss` | 確認待ちを追加しない（`id`）。`status` を `dismissed` にする |
| `stockImport` | `undo` | 自動追加を取り消す（`id`）。`stockRowId` のロットの個数を `qty` だけ減らし、`status` を `undone` にする。ロットが見つからなければ個数は変えず、返り値の `message` で知らせる |
| `coupon` | `used` / `dismiss` | クーポンを使った（`used`）・不要（`dismissed`）にする（`id`）。`used` は未使用のクーポンだけ、`dismiss` は未使用のクーポンと候補 |
| `coupon` | `remind` | 候補をクーポンにする（`id`・`title`・`validFrom`・`validUntil`。期間は `yyyy-MM-dd` か空）。内容を保存し、`status` と `notifiedOn` を空にする |

`coupon` の操作は、対象の `status` でない（すでに処理済み）ならエラーを返す。
| `todo` | `add` / `done` / `edit` / `delete` | 家事の登録・完了・編集・削除 |

返り値は `{ "status": "success" }` または `{ "status": "error", "message": "..." }`。以前の `finance`・`recurring` の書き込みには「家計簿の機能は削除しました」のエラーを返す。

## セットアップ

### 1. GAS

1. `gas/` フォルダで `clasp push` する
2. GAS エディタの「プロジェクトの設定」→「スクリプト プロパティ」に `DISCORD_WEBHOOK_URL`（Discord の Webhook URL）を追加する
   - 通知を別のチャンネルに分けたいときは、そのチャンネルの Webhook URL を次のプロパティに追加する（未設定のものは `DISCORD_WEBHOOK_URL` に送られる）
     - `DISCORD_WEBHOOK_URL_EXPIRATION`：賞味期限アラート
     - `DISCORD_WEBHOOK_URL_COUPON`：クーポンの期限と確認待ちの件数
     - `DISCORD_WEBHOOK_URL_SALE`：セールチェック
3. GAS エディタで次のトリガーを用意する
   - `setupChoreTrigger` を一度実行する（`checkChores` を5分ごとに実行するトリガーが作られる。何度実行しても重複しない）
   - `checkExpirationAndNotifyDiscord` を1日1回実行する時間主導型トリガーを作る
   - `setupSaleCheckTrigger` を一度実行する（`notifySaleCheck` を1時間ごとに実行するトリガーが作られる。何度実行しても重複しない）
   - `setupReceiptTriggers` を一度実行する（`notifyCouponsAndPending` を毎朝 7:00 に実行するトリガーが作られる。何度実行しても重複しない）。あわせて「レシート」「在庫取込」「クーポン」シートを用意し、写真の保存先のフォルダを作る。初回はドライブの権限の許可を求められる
4. Web アプリとしてデプロイし、URL を `js/common.js` の `GAS_URL` に入れる
5. 在庫のカテゴリをタグから分けるときは `migrateStockCategory` を一度実行する（在庫シートをバックアップとして複製してから、`category` 列を足し、`STOCK_CATEGORIES` にあるタグを `category` に移して `tags` から外す。在庫取込シートにも `category` 列を足す。何度実行しても結果は同じ）

通知のテストは `debugForceDiscordNotify` を実行する。セールチェックの通知文は `debugSaleCheckPreview`、クーポンの通知文は `debugCouponNotifyPreview` でログに出せる（送信もシートへの書き込みもしない）。

レシートの読み取りは、アプリの外で用意した Claude のスケジュールタスクが毎晩 0:00 に行う。「レシート」シートの `status` が空の行の写真（`fileIds`）を読み、上の「スプレッドシートの構成」のとおりに「レシート」「レシート明細」「在庫取込」「クーポン」シートへ書き込む。`status` が `再読` の行は在庫の判断だけをやり直す（在庫の自動追加では在庫シートの個数も足し、足したロットの `id` を `stockRowId` に入れる。このとき同じ商品の全ロットの `buyFlag` を空にする。新しいロットを作るときは `reorderAt` を既存のロットから写す）。

### 2. 画面

GitHub Pages でリポジトリのルートを公開する。iPhone では Safari で開き、「ホーム画面に追加」する。

## 更新の手順

### GAS を変更したとき

`clasp push` だけでは公開中の Web アプリは変わらない。デプロイを更新する（URL は変わらない）。

```sh
cd gas
clasp push
clasp deploy -i AKfycbzCsng8oDxwQnSnUlxz1m3ANECSSH1tkmK1GIhowAkyhAM_ao7BydA1venB-zGssbL1 -d "変更内容"
```

`clasp push` は GAS 側を手元の `gas/` と同じ状態にする（手元にないファイルは GAS から消える）。

### 画面を変更したとき

`main` に push すると GitHub Pages に反映される（1分ほどかかる）。

- GitHub Pages は10分間キャッシュされる。アプリのヘッダー右上の再読み込みボタンを押すと、キャッシュを使わずに最新版を読み込む
- ホーム画面のアイコンや `<head>` の `apple-mobile-web-app-*` の設定を変えたときは、ホーム画面のアイコンを削除して追加し直す必要がある

## 開発時の注意

- **見た目（テーマ「スレート」）**：暗めのグレー背景・くすんだアクセント色・丸ゴシックのダークテーマ
  - 色は `css/style.css` の `:root` の変数で決める。在庫・クーポン・家事のアクセント色（`--stock`・`--coupon`・`--chore`）と、その暗い版（`-dim`。選択中のタブなどの背景）がある。アクセント色の上に載る文字は `--on-accent`
  - 文字と背景のコントラストは本文で 4.5:1 以上にしている（`--muted` の文字は `--surface-2` の上でも 4.5:1 以上）。色を変えたときは確かめ直す
  - フォントは Google Fonts の「M PLUS Rounded 1c」。読み込めないときは端末のフォント（ヒラギノ角ゴなど）になる
- **ステータスバーの設定**：`apple-mobile-web-app-status-bar-style` は `black` にしている。`black-translucent` にすると、iOS 26 のホーム画面アプリで表示領域が画面の下端まで届かず、画面の下に空白ができる
  - ホーム画面アプリでは、iOS がステータスバーの下に少しはみ出すぼかしを重ねる（Safari では出ず、スクロールしても変わらない）。ヘッダーの上の余白を 12px にしていたときはロゴの行がぼかしにかかったため、`calc(22px + var(--safe-top))` にしている。iOS 27.2 で確かめた
- **タブバー**：画面の下に浮いた丸型のバー。背景がカードの面と近いので、縁に1pxの線（`--border`）を付けて区別している。下端から `max(12px, env(safe-area-inset-bottom) - 4px)` 離して置くので、ホームバーとは重ならない。バーの周りと下には一覧（背景は `--bg`）がそのまま見える。登録パネル・登録ボタン（FAB）・トースト・一覧の下の余白は、`--tabbar-h`（バーの高さ 66px と下の余白の合計）を基準に置いている
- **通信**：GAS の応答はふだん1〜3秒だが、混み具合によって数十秒かかることがある。そのため `js/common.js` で次のようにしている
  - 取得（`getFromGas`）：20秒で打ち切り、最大2回まで再試行する
  - 書き込み（`postToGas`）：60秒まで待つ。時間切れでも GAS 側では処理が済んでいることがあり、再試行すると二重に書き込むおそれがあるので、自動では再試行しない
  - 失敗したときは、一覧に理由（時間切れ・通信エラー・GAS のエラーの内容）と「もう一度読み込む」ボタンを出す
- **日付**：GAS は `Asia/Tokyo` で動く。家事の予定日時は、日本時間で計算する
- **写真**：送る前に画面で長い辺 1600px・JPEG（品質 0.8）に縮める（iPhone の HEIC もここで JPEG になる）。1枚ずつ送るので、時間切れになっても撮った写真がまとめて失われることはない。時間切れのときは、撮影画面の「今日撮った分」で届いたか確かめる
- **動作確認**：手元では Edge のヘッドレスモードで `index.html` を開いてスクリーンショットを撮れる（`msedge --headless=new --screenshot=... --window-size=520,900 file:///.../index.html`）。ヘッドレスの Edge は幅が約500px より狭くならない
